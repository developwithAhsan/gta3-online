How GTA III Browser Play Works

Updated 20265 min read

This site uses a WebAssembly build of the open-source re3 runtime. The browser page itself is only the launcher and runtime shell; it prepares game data, creates the WebAssembly module and then hands control to the engine.

Step 1: one-time archive download

When you choose Download & Play, the browser requests the configured authorized archive through the asset proxy. The proxy supplies CORS and range-friendly responses so the browser worker can access the file.

Step 2: persistent OPFS cache

The compressed ZIP is written to Origin Private File System storage. OPFS is private to the site origin and is designed for local browser file storage. If the cache remains available, the next visit can reuse the same ZIP instead of downloading it again.

Step 3: extract into the runtime

The current re3 build reads files through Emscripten's virtual filesystem. For that reason the cached archive is read and extracted into MEMFS for the current session before the engine starts.

Step 4: validation and launch

The launcher checks required files and important data references. When validation succeeds, it changes the engine working directory to the mounted game root and calls the WebAssembly main function.

Important: “download once” means the network archive can be reused from OPFS. It does not mean the browser can skip preparing the runtime filesystem on every fresh page session.
